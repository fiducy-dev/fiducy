# assistant-ui

`@fiducy/assistant-ui` adds a `connect_api_key` tool to an [assistant-ui](https://www.assistant-ui.com) thread. When a user has no key for the model, your chat route answers with that tool call, the thread shows the Fiducy key box, and the run continues once the user saves a key. Your app only ever stores a handle.

This page edits an app made with `npx assistant-ui create` (Next.js, AI SDK runtime). Older apps import from `@assistant-ui/react-ai-sdk` instead of `@assistant-ui/ai-sdk`; the names are the same in both.

## 1. Add Fiducy

```bash
npx fiducy init
npm install @fiducy/assistant-ui
```

`init` creates `lib/fiducy.ts` and the key route `app/api/fiducy/[...path]/route.ts` (see [Next.js](/docs/frameworks/next) for what they contain), and `npx fiducy dev --mock` gives you a local gateway. Follow [Quickstart](/docs/quickstart) steps 2 and 3 for the table and the gateway.

The `npx assistant-ui create` template has no sign-in. Add auth first; `getUserID` must return the signed-in user's ID.

You don't place the key box yourself. When a user has no key, the chat route asks for one, and the thread shows the key box as a message. That takes two edits to files the template already has.

## 2. Ask for a key in the chat route

In `app/api/chat/route.ts`, look up the user's key before calling the model. Lines marked `// Fiducy` are new or changed; the rest is the template:

<CodeGroup>

```ts title="OpenAI"
// app/api/chat/route.ts
import { createOpenAI } from '@ai-sdk/openai'; // Fiducy
import { frontendTools } from '@assistant-ui/ai-sdk';
import { requestKey, streamWithKeyRequests, withoutKeyRequests } from '@fiducy/assistant-ui/server'; // Fiducy
import { respondToMissingKey } from '@fiducy/sdk/server'; // Fiducy
import { convertToModelMessages, streamText } from 'ai';

import { fiducy } from '@/lib/fiducy'; // Fiducy

export async function POST(req: Request) {
  // Fiducy: signed out answers 401; no key yet shows the key box instead of an answer.
  const settings = await fiducy.providerSettings('openai', { request: req });
  if (!settings.ok && settings.reason === 'signed-out') return respondToMissingKey(settings);
  if (!settings.ok) return requestKey({ provider: 'openai' });

  const { messages, system, tools } = await req.json();
  const aiSDKTools = frontendTools(tools ?? {});
  const result = streamText({
    model: createOpenAI(settings).responses('gpt-4o-mini'), // Fiducy
    // Fiducy: withoutKeyRequests(...) around messages
    messages: await convertToModelMessages(withoutKeyRequests(messages), { tools: aiSDKTools }),
    system,
    tools: aiSDKTools
  });
  // Fiducy: replaces result.toUIMessageStreamResponse()
  return streamWithKeyRequests({ provider: 'openai', stream: result.stream, tools: aiSDKTools });
}
```

</CodeGroup>

- The provider factory (`createOpenAI(settings)`, `createAnthropic(settings)`, `createGoogleGenerativeAI(settings)` or `createOpenRouter(settings)`) replaces the template's provider import, so the call goes through your gateway with the user's key.
- `requestKey` answers with a short message and a `connect_api_key` call, without calling a model.
- `withoutKeyRequests` drops those turns before the next model call, so the model answers the user's original question.
- `streamWithKeyRequests` streams the answer. If the saved key is gone (revoked, or a reset dev gateway), the thread shows the key box instead of an error, and the message is answered once a key is saved. Pass `onError` to word other errors your way.
- If you switch models per request, pass the provider of the chosen model, for example `'anthropic'` for Claude.

## 3. Register the key tool in the thread

In `app/assistant.tsx`, give the runtime provider a config with `fiducyToolkit`. Again, lines marked `// Fiducy` are the change:

```tsx title="app/assistant.tsx"
'use client';

import { AssistantRuntimeProvider, AuiConfig, Tools } from '@assistant-ui/react'; // Fiducy
import { AssistantChatTransport, useChatRuntime } from '@assistant-ui/ai-sdk';
import { fiducyToolkit } from '@fiducy/assistant-ui'; // Fiducy
import { lastAssistantMessageIsCompleteWithToolCalls } from 'ai';

import { Thread } from '@/components/assistant-ui/thread';

const config = AuiConfig({ tools: Tools({ toolkit: fiducyToolkit() }) }); // Fiducy

export const Assistant = () => {
  const runtime = useChatRuntime({
    // Already in the template: resends the message once the key is saved.
    sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls,
    transport: new AssistantChatTransport({ api: '/api/chat' })
  });

  return (
    <AssistantRuntimeProvider runtime={runtime} config={config}> {/* Fiducy */}
      {/* the template's layout, unchanged */}
      <Thread />
    </AssistantRuntimeProvider>
  );
};
```

- The key box saves the handle through your `/api/fiducy` route.
- The key box reads the gateway URL and app ID from your key route, so there are no public env vars. Pass `fiducyToolkit({ basePath })` if the route is not at `/api/fiducy`.
- Your own tools go in the same `toolkit` object: `{ ...fiducyToolkit(), ...yourTools }`.
- Template paths vary by version (`thread.tsx` or `elements/thread.aui.tsx`); keep whatever import the template has.

`connect_api_key` is a human tool, so the model can call it too, for example when the user asks to add a Claude key.

## 4. Try it

Sign in, send a message. The thread answers "Connect your OpenAI key to keep going" with the key box. Save a key, and the original message is answered. With `npx fiducy dev --mock`, any string works as a key. The fake OpenAI answers both the Chat Completions API (`.chat(...)`) and the Responses API (`openai(...)` or `.responses(...)`, the template's default).

If the thread shows "Waiting on tool: connect_api_key" with Allow and Deny buttons instead of the key box, the tool isn't registered: check that `<AssistantRuntimeProvider>` has `config={config}`. Start a new chat after fixing it.

## Styling

The tool renders plain elements with `fiducy-tool`, `fiducy-tool-title`, `fiducy-tool-widget`, `fiducy-tool-error` and `fiducy-tool-done` classes. Style them to match your thread.
