# Quickstart

This adds Fiducy to an app you already have. Fiducy is not a framework and does not create an app; it adds a few files to yours.

**Before you start:** your app needs sign-in. Fiducy stores each key for a signed-in user. Any auth with a server session works ([Better Auth](https://www.better-auth.com), [Auth.js](https://authjs.dev), [Clerk](https://clerk.com) or your own).

## 1. Run init

In the root of your app:

```bash
npx fiducy init
```

It detects your framework, package manager, auth and database, then:

- creates your **server module** (for example `lib/fiducy.ts`), wired to your auth and database
- creates the **key route** your framework needs (for example `app/api/fiducy/[...path]/route.ts`)
- installs `@fiducy/sdk`
- prints the few lines that belong in files you already have, such as a route list or a hooks file

It never edits an existing file. Run `npx fiducy init --dry-run` first to see everything without writing. Prefer to do it by hand? Every framework page shows the exact files: [Next.js](/docs/frameworks/next), [TanStack Start](/docs/frameworks/tanstack-start), [React Router](/docs/frameworks/react-router), [SvelteKit](/docs/frameworks/sveltekit), [Nuxt](/docs/frameworks/nuxt), [Express and Node](/docs/frameworks/express), [Farm.js](/docs/frameworks/farm), [anything else](/docs/frameworks).

The server module looks like this (Next.js with Better Auth and no database yet):

```ts title="lib/fiducy.ts"
import { mkdirSync } from 'node:fs';
import { DatabaseSync } from 'node:sqlite';

import { createFiducy } from '@fiducy/sdk/server';
import { kyselyStorage } from '@fiducy/sdk/storage/kysely';

import { auth } from '@/lib/auth';

mkdirSync('.fiducy', { recursive: true });

export const fiducy = createFiducy({
  storage: kyselyStorage(new DatabaseSync('.fiducy/keys.sqlite')),
  getUserID: async (request) => {
    const session = await auth.api.getSession({ headers: request.headers });
    return session?.user.id ?? null;
  }
});
```

- **`getUserID`** returns the signed-in user's ID from your auth's server session, or `null`. Never read it from the body, the query or a header the browser sets. If init found no auth, it writes a `readSignedInUserID` function that throws until you fill it in.
- **`storage`** keeps each user's key handle (a reference, never the key). Init uses your Prisma, Drizzle or Kysely database when it finds one, and a local SQLite file otherwise. Swap that for your real database before you deploy; see [Storage](/docs/storage).
- The gateway URL, app ID and app secret come from your server environment (step 3). There is nothing to pass.

## 2. Create the table

```bash
npx fiducy migrate     # Kysely storage, including the SQLite file
npx fiducy generate    # Drizzle or Prisma: writes the table, then run their migrate
```

See [CLI](/docs/cli#generate) for what each writes.

## 3. Start a local gateway

```bash
npx fiducy dev --mock
```

This runs a gateway on `http://localhost:3438` for development. On the first run it writes `.env` with `FIDUCY_GATEWAY_URL`, `FIDUCY_APP_ID` and `FIDUCY_APP_SECRET` (or prints them if you already have a `.env`). Restart your dev server so it loads them. `--mock` answers model calls with a fake model, so any string works as a key while you build. Keys survive restarts; delete `.fiducy/` to start fresh.

In production, use your own deployed gateway and the values from its dashboard; see [Self-hosting](/docs/self-hosting).

## 4. Show the key widget

The widget asks for the key in an iframe served by your gateway and saves the returned handle through your key route. It reads its settings from that route, so it needs no props apart from the provider:

<CodeGroup>

```tsx title="React"
'use client';

import { FiducyKey } from '@fiducy/sdk/react';

export const KeySettings = () => <FiducyKey provider="openai" />;
```

```vue title="Vue"
<script setup lang="ts">
import { FiducyKey } from '@fiducy/sdk/vue';
</script>

<template>
  <FiducyKey provider="openai" />
</template>
```

```svelte title="Svelte"
<script>
  import { fiducyKey } from '@fiducy/sdk/svelte';
</script>

<div use:fiducyKey={{ provider: 'openai' }}></div>
```

```html title="HTML"
<script type="module">
  import '@fiducy/sdk/element';
</script>
<fiducy-key provider="openai"></fiducy-key>
```

</CodeGroup>

Signed out, it says so. Signed in without a key, it shows the key box. With a key, it shows "OpenAI key connected" with Replace and Remove. See [Key widget](/docs/widget) for events and styling, and [Solid](/docs/widget/solid).

## 5. Call the model with the user's key

```ts title="app/api/chat/route.ts"
import { createOpenAI } from '@ai-sdk/openai';
import { respondToMissingKey } from '@fiducy/sdk/server';
import { streamText } from 'ai';

import { fiducy } from '@/lib/fiducy';

export async function POST(request: Request) {
  const settings = await fiducy.providerSettings('openai', { request });
  if (!settings.ok) return respondToMissingKey(settings);

  const { messages } = await request.json();
  const result = streamText({ model: createOpenAI(settings).responses('gpt-4o-mini'), messages });
  return result.toUIMessageStreamResponse();
}
```

`providerSettings` returns `{ ok: true, baseURL, apiKey, headers, fetch }` pointing at your gateway, or `{ ok: false, reason }` with `reason` `'signed-out'` or `'no-key'`. `respondToMissingKey` turns that into `401` ("Sign in to use your OpenAI key") or `409` ("Connect your OpenAI key to keep going") with the provider in `data`, so your page can show the widget. Never fall back to a key of your own.

The settings work with any client that takes a base URL and headers:

<CodeGroup>

```ts title="OpenAI SDK"
import OpenAI from 'openai';

const { baseURL, apiKey, headers } = settings;
const openai = new OpenAI({ baseURL, apiKey, defaultHeaders: headers });
```

```ts title="fetch"
const { baseURL, apiKey, headers } = settings;
const response = await fetch(`${baseURL}/chat/completions`, {
  method: 'POST',
  headers: { ...headers, authorization: `Bearer ${apiKey}`, 'content-type': 'application/json' },
  body: JSON.stringify({ model: 'gpt-4o-mini', messages })
});
```

</CodeGroup>

For Anthropic, `createAnthropic(settings)` from the AI SDK works as is. The official Anthropic SDK adds `/v1` itself, so give it `baseURL.replace(/\/v1$/, '')`.

## 6. Try it

1. Open your app signed out: the widget says "Sign in to connect your OpenAI key."
2. Sign in: the key box appears. Paste any string (with `--mock`) and save.
3. Send a message: the reply comes back through the gateway.

Using assistant-ui? [`@fiducy/assistant-ui`](/docs/assistant-ui) opens the key box inside the thread when a key is missing and resends the message once it is saved. Something off? See [Gotchas](/docs/gotchas).
