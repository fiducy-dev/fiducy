# Gateway API

The SDK wraps all of these. You only need this page for custom clients.

Every response is JSON `{ data, message }`, except provider proxy responses, which are passed through untouched.

## Authentication

Server calls send the app secret: `authorization: Bearer fsk_...`. The widget's `POST /keys` is authenticated by the browser origin instead.

## Endpoints

| Method and path | Who calls it | Purpose |
| --- | --- | --- |
| `GET /health` | anyone | Liveness |
| `GET /attestation?nonce=` | anyone | Nitro attestation document for the running enclave |
| `GET /widget?app=&origin=` | the iframe | Key entry page. CSP locks `frame-ancestors` to `origin` |
| `POST /keys` | the iframe | Seal a key. Returns `{ handle }` or `{ handle, record }` |
| `POST /keys/import` | your server | Seal up to 100 keys you already store: `{ apiKeys: [...] }`. Returns `{ keys: [{ handle, record? }] }` in the same order. Off unless the app turns on key import |
| `DELETE /keys/:keyID` | your server | Revoke (Fiducy-stored records only) |
| `ANY /{provider}/...` | your server | Proxy to the provider with the user's key |

## Provider proxy

| Provider | Gateway base URL |
| --- | --- |
| OpenAI | `/openai/v1` |
| Anthropic | `/anthropic/v1` |
| Gemini | `/gemini/v1beta` |
| OpenRouter | `/openrouter/api/v1` |

Headers:

| Header | Value |
| --- | --- |
| `authorization` | `Bearer fsk_...` (your app secret, not the user's key) |
| `x-key-handle` | `kh_...` |
| `x-key-record` | base64url JSON record, only in app-owned mode |

Errors from the gateway itself:

| Status | Meaning |
| --- | --- |
| `400` | Missing or malformed handle or record |
| `401` | Bad app secret |
| `403` | The handle belongs to another app or cannot open its key, a key was added outside the widget, or the endpoint can't be priced while spend limits are on |
| `404` | No key with this ID for this app |
| `409` | Revoke through the gateway on an app that stores its own records. Delete the record instead |
| `429` | The key reached its monthly request limit, a spend limit was reached, or the key has too many requests running at once. The message says which |

## Spend limits

An app can set spend limits. The gateway enforces them inside the enclave, before the user's key is used, so a leaked app secret can't spend more than they allow. Any limit you leave out is off.

| Setting | What it caps |
| --- | --- |
| `dailyDollarLimitPerKey` | Estimated US dollars per user key per UTC day |
| `dailyDollarLimitPerApp` | Estimated US dollars across all of the app's keys per UTC day |
| `minuteDollarLimitPerApp` | Estimated US dollars across all of the app's keys per minute |
| `concurrentRequestLimitPerKey` | Requests running at once with one key |
| `maximumOutputTokens` | Output tokens one request may ask for. Default `32768` once any spend limit is set |

How it works:

- Before the call, the gateway reserves the worst case: the request's input (estimated from its size) plus its output limit, at the model's price. If that would pass a limit, it answers `429` and the call never reaches the provider.
- After the call, it replaces the reservation with the real cost from the provider's token counts. A provider error refunds it. A stream that stops early keeps the full reservation, since the provider may still bill for it.
- It sets or lowers `max_tokens`, `max_completion_tokens`, `max_output_tokens` or Gemini's `maxOutputTokens` to `maximumOutputTokens`, and turns on `stream_options.include_usage` for OpenAI streams so the real cost can be read.
- Only endpoints it can price are allowed: chat completions, completions, Responses, embeddings, Anthropic messages and token counts, Gemini generate, count and embed calls, and OpenRouter completions. Other `POST` endpoints (files, batches, images, audio) answer `403`. `GET` requests pass.
- Prices come from a table in `@fiducy/providers` (`packages/providers/src/prices.ts`). A model it doesn't know is priced at the dearest model in the table, so a new model is never cheaper than it should be.
- With `FIDUCY_KEYS_TABLE` set, the totals live in that DynamoDB table and hold across restarts and enclaves. Without it they live in memory. The running-request count is per gateway process.

Set them in the dashboard under the app's settings, or in `FIDUCY_APPS_JSON`:

```json
[{
  "appID": "app_demo",
  "name": "Demo",
  "appSecret": "fsk_demo_local",
  "monthlyRequestLimitPerKey": 10000,
  "allowedOrigins": ["http://localhost:3000"],
  "spendLimits": {
    "dailyDollarLimitPerKey": 5,
    "dailyDollarLimitPerApp": 200,
    "minuteDollarLimitPerApp": 10,
    "concurrentRequestLimitPerKey": 4,
    "maximumOutputTokens": 32768
  }
}]
```
