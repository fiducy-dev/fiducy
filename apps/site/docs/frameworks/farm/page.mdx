# Farm.js

On [Farm.js](https://farmjs.dev), the `@fiducy/farm` integration mounts the key routes for you. The working version is [`examples/farm`](https://github.com/fiducy-dev/fiducy/tree/main/examples/farm).

```bash
npx fiducy init
```

Or by hand: `npm install @fiducy/sdk @fiducy/farm`, then the files below. The example below keeps handles in a Farm storage mount; any [storage adapter](/docs/storage) works too.

## Run the example

Copy the example app and run it with a local gateway:

```bash
npx degit fiducy-dev/fiducy/examples/farm my-app
cd my-app
npm install
npx fiducy dev --mock
```

`fiducy dev` writes its settings to `.env` and keeps running. In a second terminal, start the app:

```bash
npm run dev
```

Sign in as the test user, paste any string as the key (`--mock` answers with a fake model), and ask a question. The example signs users in with a test cookie and keeps handles in a JSON file (`example-kit`); swap both for your own auth and [storage](/docs/storage).

## Server module

```ts title="src/lib/fiducy.ts"
import { auth } from '@farm.js/auth/server';
import { getStorage } from '@farm.js/core/storage';
import { createFiducy, keyValueStorage } from '@fiducy/sdk/server';

export async function getUserID(request: Request) {
  const user = await auth.user({ request });
  return user?.id ?? null;
}

export const fiducyServer = createFiducy({
  storage: keyValueStorage({
    getItem: (key) => getStorage('fiducy').getItem(key),
    setItem: (key, value) => getStorage('fiducy').setItem(key, value),
    removeItem: (key) => getStorage('fiducy').removeItem(key),
    getKeys: (base) => getStorage('fiducy').getKeys(base)
  }),
  getUserID
});
```

Three Farm details:

- **Look the mount up on every call**, as above. This file is imported by `farm.config.ts`, which loads before Farm sets up its storage mounts, so `keyValueStorage(getStorage('fiducy'))` would capture a different store than your routes use, and `providerSettings` would return `null`.
- **Pass `request` to `auth.user`.** The integration's routes run outside Farm's page request, so `auth.user()` without it throws "No current request is available".
- **Set `FARM_AUTH_URL`** when your app is not on port 3000. Farm Auth signs cookies for `http://localhost:3000` in development, so on another port add `FARM_AUTH_URL=http://localhost:5173` to `.env`, or sign-in fails with "Invalid origin".

## Integration

```ts title="farm.config.ts"
import { defineConfig } from '@farm.js/core';
import { localStorage } from '@farm.js/core/storage';
import { fiducy } from '@fiducy/farm';

import { fiducyServer } from './src/lib/fiducy';

export default defineConfig({
  storage: {
    mounts: { fiducy: localStorage({ base: '.data/fiducy' }) }
  },
  integrations: {
    byok: fiducy({ instance: fiducyServer })
  }
});
```

Farm's `localStorage` driver writes files on your server under `.data/fiducy` (it is not the browser's localStorage). That is fine while developing; in production, point the mount at a database, for example `postgresStorage({ url: process.env.DATABASE_URL })` from `@farm.js/core/storage`.

The integration mounts the [key route](/docs/frameworks#what-every-framework-needs) at `/api/fiducy`. Name the instance `fiducyServer` (or anything but `fiducy`) so it does not clash with the integration's import in `farm.config.ts`.

## Model route

<CodeGroup>

```ts title="OpenAI"
// src/app/api/chat/route.ts
import { createOpenAI } from '@ai-sdk/openai';
import { respondToMissingKey } from '@fiducy/sdk/server';
import { streamText } from 'ai';

import { fiducyServer } from '@/lib/fiducy';

export async function POST(request: Request) {
  const settings = await fiducyServer.providerSettings('openai', { request });
  if (!settings.ok) return respondToMissingKey(settings);
  const { messages } = await request.json();
  const model = createOpenAI(settings).responses('gpt-4o-mini');
  return streamText({ model, messages }).toUIMessageStreamResponse();
}
```
